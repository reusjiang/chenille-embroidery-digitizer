# 以 DST 样本库驱动的订单生成路线

更新：2026-10-13。根据项目所有者确认，`assets/private/dst-library/` 内的 DST 可以直接作为输出范例使用。后续开发优先检索复用这些成果，再逐步抽取可组合的字母、数字和连接规则。本文件是开发路线，不代表下述检索、分段和组合能力已经实现。

已落实的目录与字段见 [目录职责与工作流](repository-layout.md)。目前已完成首版只读索引、覆盖盘点和 v002 实验补录，订单匹配与字母组合仍待实现。

## 1. 样本库是输出依据

人工 DST 同时承担三个角色：完整订单的直接复用文件、局部笔顺与针迹的来源、新生成结果的对照范例。不再把每个已有整词都重新拟合成一个新 DST。

本次只读盘点发现 2,597 个 DST：font1 为 1,210 个，fon2 为 234 个，font3 为 1,153 个；目录 fon2 映射到 Font2。按文件 SHA256 去重后为 2,596 份内容，存在一组相同内容。全部可被当前 DST 读取器读取，但此盘点不是完整文件校验或实机验收。

有 117 个文件名含数字；数字可能表示真实文字、尺寸或文件版本，不能仅凭文件名判为数字字形覆盖。文件名得到的字母集合也只能作为待核对线索。尺寸统计中存在零宽度样本，建索引时需要分类检查，不能把所有文件默认视为可直接交付的完整订单。

用户确认的“可作为输出范例”单独记录为参考依据，不自动填充历史机器型号、材料或试绣通过记录。已经确认可直接交付的适用条件应进入样本元数据。

## 2. 订单处理按四种情况选择

| 情况 | 处理方式 | 必须记录 |
|---|---|---|
| 已有相同文字、大小写、字体、布局、尺寸及适用工艺的完整样本 | 复制原 DST 字节作为该订单输出，不重新拟合 | 订单 ID、样本 ID、原始 SHA256、选择依据、文件检查 |
| 已有相同文字与字体，但尺寸或排版不同 | 以样本针路及笔顺为基础，重建所需尺寸和布局，重新安排针距及起收 | 原样本、变换、重新采样参数、变化后文件校验与适用范围 |
| 没有整词，但字母/数字及连接结构已有覆盖 | 按字体和上下文组合已标注笔段，生成新的完整路径，再统一生成针迹 | 各片段来源、连接规则、笔顺、起收/跳转策略、覆盖缺口 |
| 存在未覆盖字符、连接、装饰或布局 | 定位缺口，制作少量新范例或人工修正，将审查后的结果收入库 | 新增规则及样本、验证订单、适用条件和回退依据 |

字体、文字和尺寸匹配不能只靠文件名。订单字体识别或样本匹配存在歧义时，展示候选供确认。原文件直接复用与调整后生成在交付记录中明确区分。

## 3. 有限字符如何支持更多订单

先定义目标字符集：三种字体下的大小写字母、数字，以及实际订单出现的空格、连字符、句点等符号。字符集合有限，但整词组合随长度增长；只收集单字母不能覆盖连笔和笔顺的变化。

样本分四层组织：

1. 整词/完整设计：最快交付重复订单，保存多尺寸和多布局变体。
2. 字母/数字：标注笔段、进出位置、回走、交叉、独立点与横画，不直接按矩形裁切针迹。
3. 连接与上下文：记录相邻字符、词首/词中/词尾、进入和离开方向、局部空间及是否需要跳转。不能把不同字体的同名字符直接互换。
4. 工艺配置：记录目标设备、材料、尺寸范围下经过验证的针距、转弯、回线和补偿。

字符片段中的整词起收针不能机械重复拼接；要区分字母主路与原设计起收段，在新完整路径上按连续段和跳转重新处理。先保持字体比例和设计要求，再做工艺处理。

## 4. 实施顺序和完成条件

| 阶段 | 建设内容 | 完成条件 |
|---|---|---|
| A：整词检索输出 | 建立带哈希的索引，核对文字、字体、尺寸和布局；接收结构化订单 | 能从订单匹配已知样本，原字节输出 DST，并提供可追溯交付记录；歧义不静默选取 |
| B：订单 PDF 接入 | 将订单识别结果转换为同一结构化输入，保留来源页和字段确认状态 | 核对文字、大小写、字体、宽度及分行，能沿用 A 的匹配输出流程 |
| C：字母数字与连接库 | 从完整样本标注片段和上下文，按真实订单频率补缺口 | 新词生成不读取对应整词 DST，能说明每段来源；不存在的连接不擅自补线 |
| D：统一生成及实机收敛 | 按订单组合路径、采样、导出，基于反馈调整规则或工艺配置 | 新订单通过文件检查；代表性工艺条件完成操作方验证；旧接受案例无未解释退步 |

v002 的三款用于验证曲线重建、回线与采样策略；它们不能单独证明组合新词的能力。A 可优先交付实用能力，同时用 v002 开展工艺验证，不必等所有字符连接都收齐才开始处理订单。

## 5. 每轮反馈怎样成为通用能力

每轮保存：问题与假设、对应订单/样本/试绣 ID、代码提交、规则及工艺版本、输入和输出哈希、修改前后对照、回归结果、操作方判定、接受或回退决定。

先分清问题来源：订单识别错误修正识别或确认流程；选错样本修正索引与匹配；字形或连接错误修正笔段和组合规则；堆线、松脱等问题结合实机对照调整工艺。不要用全局针距修改掩盖某个样本标注错误。

经核对的规则改动进入生成器；经接受的新完整设计进入样本库；失败结果同样保存。原始 DST 不覆盖，索引修正、规则和新输出分别版本化。

## 6. 分开验证复用能力和新词能力

已有整词复用：在匹配测试中核对正确文字、字体、布局、尺寸和输出字节，不将它计入新词泛化成绩。

新词组合：在规则抽取前保留一组未参与调参的完整词。同词变体、重复字节及该词的衍生结果不能泄漏到它自己的调参组；被保留的整词 DST 仅供生成后对照，不作为该词生成输入。

逐轮记录：准确整词匹配率、符合直接复用条件的订单占比、已核对字符覆盖、连接上下文覆盖、未见词通过情况、实机故障及接受情况。数字字形必须经内容核对后再计入覆盖。

“通用版本”首先指已声明的三种字体、字符、尺寸和工艺范围。遇到范围外订单显式记录缺口，通过新样本扩大覆盖。

## 7. 版本与交付关系

每个订单保存一条生成记录：订单输入 → 生成器提交 → 样本索引版本/原文件哈希 → 笔段和连接规则版本 → 工艺配置 → 最终 DST 哈希 → 试绣记录。

生成器版本、样本库版本、订单候选版本分别编号。一个生成器可处理多个订单；同一订单可有多个候选。即使通过原文件复制交付，也保留订单与原样本绑定关系。

样本库是运行时资源；向设备操作方交付的是当前订单的 DST、回放与反馈表。部署完整生成系统时另行明确所需样本和字体资源，不能只交付脚本却遗漏它依赖的库。
