# 目录结构与每轮工作流

本次调整采用新增工作区方式，原始 DST、字体、历史生成脚本及已发布 v001/v002 路径保持原样。新目录已放入索引工具、首版索引、实际 v002 实验记录与字段模板；不代表订单识别和新词组合已经完成。

| 目录 | 职责 | 内容来源 |
|---|---|---|
| assets/private/ | 原始 DST、字体和订单 PDF | 保留原路径，不用目录名推断 Git 状态 |
| library/catalog/ | 按内容 ID 管理的版本索引 | index_library.py 自动构建 |
| library/annotations/ | 文字、字体和笔段标注 | 人工核对或带证据的标注 |
| library/coverage/ | 已覆盖内容及待补缺口 | 首版仅盘点及文件名线索 |
| rules/fonts/ | 字体、笔顺和连接规则 | 从多样本归纳并验证 |
| rules/processes/ | 软件策略及设备材料配置 | v002 参数引用、后续试绣依据 |
| configs/ | 一次运行选择的输入及参数 | 版本化运行配置 |
| orders/ | 订单字段和每次生成的绑定记录 | 模板及本地订单工作区 |
| experiments/ | 每轮假设、变更、证据和决定 | 实验记录，不复制原始照片 |
| src/chenille/ | 可复用引擎逻辑 | 现已实现样本索引模块 |
| scripts/ | 命令入口与历史复现脚本 | 保持旧流程兼容 |
| examples/、tests/ | 可复现案例与回归检查 | 经选择的输入和自动检查 |
| feedback/ | 操作方原始/整理反馈 | 以实际 DST 和试绣 ID 绑定 |
| releases/ | 冻结的订单候选交付 | 不覆盖旧版本 |
| build/、dist/ | 临时候选、操作方 ZIP | 可重新生成，不作为唯一存档 |

## 后续每轮按这个顺序保存

1. 样本库有变化，创建新的 catalog/coverage 版本，原字节保留。人工确认内容写入独立 annotations 文件。
2. 订单写入 orders/local/<order-id>/，记录输入哈希及核对状态。PDF 原件留在原资料目录。
3. 若要调整规则，先建立 experiments/<date>-<topic>/，写清问题、假设、对照和固定条件。
4. 使用确定的代码、样本、标注、规则和配置生成 build/ 候选；生成记录绑定各版本和输出哈希。
5. 校验后冻结到新的 releases/ 目录；设备方只领取该候选交付包。试绣反馈通过版本、样本和实验 ID 回传。
6. 记录接受或回退及适用范围；有效完整设计入库，有效局部策略进入规则。未接受候选不自动替换已接受规则。

目前第 1 步索引及核对工具已实现；订单字段和规则/实验记录采用文档模板，尚无自动工作流执行器。

## Git 与兼容约定

新源码、索引、模板及脱敏后的规则/实验记录可进入 Git；orders/local/ 的新增订单和 feedback/inbox/ 默认排除。索引包含源文件名，跟随样本资料的共享范围管理。

当前仓库已有 assets/private/ 内容被跟踪；本次不删除、不取消跟踪、不修改其共享设置。仅修正文档中过时的“自动排除”描述。保持旧发布路径与清单，不迁移被构建记录绑定的历史源码。
